# 港口集装箱装卸延误分级

`container-delay-triage` 面向海陵港集装箱运营台。调度员把船次窗口、箱单核验、闸口事件汇总为人工交叉特征，worker 用 LogisticRegression 给延误案件分级，再由主管确认调度动作。

## 账号

- `operator / operator123` 现场调度员，可维护船次、箱单、闸口记录并发起分级
- `supervisor / supervisor123` 船舶值班主管，可处理查验状态、冲正闸口、派发调度动作
- `viewer / viewer123` 运营观察员，只读看板和分级结果

## 运行

```bash
docker compose up -d --build
# 浏览器访问 http://localhost:18262
```

## 交付范围

船期窗口、箱单核验、闸口记录、延误案件、调度处置五个业务模块，包含查验未结束拒绝普通延误和重复闸口必须冲正两个异常分支。算法任务由 Redis 队列交给 worker，结果写回 `analysis_jobs` 和 `delay_cases`。


## 业务核验模块

登录后打开页面右下角的「业务核验」。可从实时业务台账筛选记录、导出所选结果，主管可对当前证据签认并填写说明。

- **查验积压与船期** 按挂靠汇总海关状态和封签问题，优先处理阻塞箱量最大的船期。
- **闸口拥堵分布** 分闸口和作业日统计有效停留，冲正记录单列；高于 60 分钟的有效记录列为拥堵。
- **调度交接时限** 把案件等级、责任人和到期时间放在同一交接表，区分未完成逾期和完成后超时。

### 二次扩展核验

- **装船进闸凭证核对** 逐箱核对有效进闸凭证与查验状态，区分未放行、缺凭证和已齐备。
- **分流阻断恢复队列** 结合案件状态与最近模型任务，区分业务输入待修、模型失败待重跑和待人工定级。

## 业务处置与验收

登录后打开「港口异常交接」。操作员提交结果、凭证号和说明，主管可复核关闭或退回补证，观察员可查看记录。关闭时复查源业务状态，处置历史保留每次操作。

- 重复进闸冲正复核
- 分流恢复验收
- 海关放行交接

### 船方申诉 · 分级说明

主管在「港口异常交接 → 分流恢复验收」选中案件后，可在页面下方查阅或签发分级说明；「调度详情」页每个处置动作也提供「分级说明」查阅入口。

- 派工落库时同时冻结**当时采用的推理任务**（`dispatch_actions.analysis_job_id`）与**等级快照**（`graded_level_snapshot`），说明必须对得上该等级，等级与推理判定不一致时拒绝签发。
- worker 推理时把 StandardScaler 参数、各类别截距/系数与特征快照冻结进 `analysis_jobs.result.model_evidence`。说明按该次推理重建多分类 LR 决策分差：**分差 = 基础分差（截距差）+ Σ 各特征贡献**，逐特征列出对「领先等级领先次高等级」的分差贡献，页面给出核对结论，可核回原判断。
- 已签说明为冻结原件（`grade_explanations`，按案件+处置动作幂等），案件后续重新分级不影响已签说明，仍照原件查阅。
- 旧单若缺少冻结证据（如演示数据中的历史派工），页面显示「无法追溯」且不能补造说明。
- 签发中断后重试命中同一幂等键，返回原单、不重复出单（数据库唯一约束兜底并发）。
